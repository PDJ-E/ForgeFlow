# Harness v2b — task-scoped rounds and in-loop verification

- **Branch:** `feat/harness-v2b` (after v2a is merged)
- **Why:** ADR 0006 §1–3. The unit of execution becomes the plan task; the builder can run
  the configured checks itself.
- **Depends on:** [`2026-11-01-harness-v2a.md`](2026-11-01-harness-v2a.md) (telemetry,
  budgets, `Files:` per task).
- **Out of scope:** review contract (J5/C.1), J6, Codex, per-task model review, builder
  subagents.

## Tasks

### T1: Parse tasks and slice the builder prompt

- **Goal:** The builder sees one task in full plus the plan's frame, not the whole plan.
- **Files:** `forgeflow/design.py`, `forgeflow/prompts.py`, `forgeflow/providers.py`,
  `tests/test_design.py`, `tests/test_prompts.py` (new)
- [ ] Done when: a pure function returns the plan's tasks (id, title, body, criteria, files)
  and the frame sections (objective, requirements, scope); a plan without parseable tasks
  yields one task holding the whole plan.
- [ ] Done when: `ProviderTask` carries the current task id; the builder prompt contains the
  frame, the current task in full, other tasks as `id: title [done|pending]`, and the plan
  hash; `plan_text` and its hash check are unchanged.
- **Verify:** `py -3.13 -m unittest tests.test_design tests.test_prompts -v`

### T2: Run, commit and check task by task

- **Goal:** A round iterates tasks; each finished task is committed and checked.
- **Files:** `forgeflow/pipeline.py`, `forgeflow/dispatch.py`, `forgeflow/store.py`,
  `tests/test_pipeline.py`, `tests/pipeline_support.py`
- [ ] Done when: each task gets its own builder invocation, scope check and commit
  (`forgeflow: J<n> T<k> round <r>`), then the configured checks; a `task-result` evidence
  record holds task, commit, status, checks and usage.
- [ ] Done when: a task with failing checks is retried within a per-task limit with the
  failures as feedback; past the limit the job goes to `needs_human` naming the task, with
  earlier tasks' commits intact.
- [ ] Done when: after the last task the existing verify → review → deliver flow runs on the
  final commit unchanged (existing pipeline tests pass untouched).
- **Verify:** `py -3.13 -m unittest tests.test_pipeline -v`

### T3: Resume from the first unfinished task

- **Goal:** Interruptions and timeouts cost at most one task.
- **Files:** `forgeflow/pipeline.py`, `tests/test_recovery.py`, `tests/test_interruption.py`
- [ ] Done when: after a kill during task k (real child orchestrator test), `resume` keeps
  tasks < k committed, keeps task k's uncommitted partial work in the worktree, and restarts
  at task k with a note that partial work exists.
- [ ] Done when: rework rounds after review re-run only the tasks named by the open findings
  (or all tasks when a finding has no task), within the existing `max_rework` budget.
- **Verify:** `py -3.13 -m unittest tests.test_recovery tests.test_interruption -v`

### T4: Let the Claude builder run the configured checks

- **Goal:** The builder closes its own feedback loop (ADR 0006 §3).
- **Files:** `forgeflow/providers.py`, `forgeflow/prompts.py`, `forgeflow/environment.py`,
  `tests/test_providers.py`, `docs/decisions/0005-build-review-and-delivery.md`
- [ ] Done when: the builder argv adds `Bash` with `--allowedTools` entries built from the
  exact configured check argv (plus `git status`, `git diff`), `--permission-mode dontAsk`;
  a fake-CLI test asserts nothing broader is allowed and the reviewer argv is unchanged.
- [ ] Done when: the builder prompt tells it to run the narrowest relevant check after each
  change and the full checks before finishing; ForgeFlow still runs its own checks.
- [ ] Done when: `doctor` shows the builder's allowed commands.
- **Verify:** `py -3.13 -m unittest tests.test_providers tests.test_environment_cli -v`

### T5: Documentation and live validation

- **Goal:** Docs match behaviour; one real run proves it.
- **Files:** `docs/decisions/0006-task-scoped-execution-harness.md`, `docs/roadmap.md`,
  `docs/architecture.md`, `docs/getting-started.md`, `CHANGELOG.md`
- [ ] Done when: ADR 0006 is `Accepted` with the live-run record; the roadmap lists Harness
  v2 before C.1, re-scopes C.1 as split jobs, and fixes the stale Checkpoint C header.
- [ ] Done when: with the owner's authorisation, one `--builder claude --reviewer claude`
  run on a small 2–3 task plan reaches a draft PR; the record lists per-task commits, check
  results, turns, cost and duration per task.
- **Verify:** full checks; the live run is not a CI dependency.

### T2 — 2026-11-01 — T1 committed as 94ceadf
- A plan with tasks: `dispatch.start_build` (the old dispatch guards, then → BUILDING once per
  round), then per task `dispatch.build_step` (guards again, execute, `provider-result`, scope

  the same task again with `check_failures(payload)` as feedback; after `MAX_TASK_ATTEMPTS` (3)

  report line "the plan has no '### T<n>: <title>' tasks; building it in one run".

    Cost: one extra check run per round (~3 min for this repository's suite).
  - A task that changes nothing (after earlier commits) is recorded `build-commit unchanged`
